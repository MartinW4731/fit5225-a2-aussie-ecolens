# Phase 2 – Real ML Model Integration

## Changes Made

The original Phase 1 implementation used a placeholder detection logic that returned predefined species labels based on the uploaded file name.

For Phase 2, the service was updated to use the provided Oracle ML models for real image classification.

### Main Changes

1. Added ml_pipeline.py
   - Loads the provided model files.
   - Runs image preprocessing and model inference.
   - Returns predicted species and confidence score.

2. Updated app.py
   - Replaced the placeholder detection logic.
   - /detect now calls the ML pipeline for real prediction.
   - Returns prediction results generated by the model.

3. Added model files
   - mdv5a.pt
   - model.pt
   - labels.txt
   - config.yaml

4. Updated Docker configuration
   - Added required dependencies for model loading.
   - Switched to Python 3.10 Docker image for compatibility with ONNX and MegaDetector dependencies.

---

## Model Files

The following files must exist in the service directory:

text mdv5a.pt model.pt labels.txt config.yaml 

These files are loaded automatically when the service starts.

---

## Build Docker Image

bash docker build --no-cache -t oracle-ml-service:latest . 

---

## Run Service

bash docker run --rm -p 8080:8080 oracle-ml-service:latest 

---

## Health Check

bash curl http://localhost:8080/ 

Expected response:

json {   "status": "Oracle ML service is running" } 

---

## Test Detection Endpoint

Prepare a JSON request file:

json {   "file_name": "test.jpg",   "file_type": "image",   "image_base64": "<base64_encoded_image>" } 

Save it as:

text test.json 

Run:

bash curl -X POST http://localhost:8080/detect \   -H "Content-Type: application/json" \   --data-binary @test.json 

Example response:

json {   "confidence": {     "Alectura_lathami": 0.999983549118042   },   "source": "Oracle ML detection",   "tags": {     "Alectura_lathami": 1   } } 

This confirms that the service is using the real Oracle ML models instead of the Phase 1 placeholder logic.
